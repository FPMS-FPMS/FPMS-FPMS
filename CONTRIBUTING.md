# Contributing to FPMS

FPMS is a student competition project, so "contribution" here mostly means feedback, questions, and honest critique — not pull requests. But if you'd like to be involved, here's how.

## If you have feedback

Open an issue. Especially welcome:

- **Technical review** — if you see something in our architecture, code, or approach that looks wrong, please say so
- **Indigenous community feedback** — if you're a community member and see something we're getting wrong in our framing, outreach, or design, please tell us (see [outreach-notes.md](outreach-notes.md))
- **Judges/educators** — if you're evaluating this project for WRO or a similar context and want more detail on any decision, ask

## If you'd like to help

We are two Grade 7 students, and we welcome mentorship. Areas where we know we could learn more:

- ROS2 Nav2 tuning for small indoor rovers
- YOLO training on domain-specific data (fire, brush, heritage markers)
- Cultural sensitivity in robotics outreach
- AWS IoT deployment patterns

## What we ask

- Assume good faith in our questions — we are learning
- Be direct with critique; we would rather hear it clearly than politely
- Please don't romanticize our age; treat the technical work on its merits

## Code of conduct

Be kind. Be honest. If in doubt, err toward the community whose knowledge and land this project centers.
